# Patient clerking

`/app/clerking` is a consent-based guided history interview, with browser
speech recognition, spoken prompts and typed fallback. It follows the owner's
nine headings: Biodata, Presenting Complaint, History of Presenting Complaint,
Past Medical History, Drug History, Family History, Social History, Review of
Systems and Summary. These are headings for an interview, not an exhaustive
clinical questionnaire or triage system.

The patient answers each question using Speak answer, then stops the microphone
to check the transcript and moves to the next question. This is a turn-based
voice interview, not an always-listening realtime voice agent. English Nigeria,
UK and US recognition preferences are available; support and quality depend on
the browser, device and speech service. Microphone denial and unsupported browsers
have a typed fallback. Prompts and AI clarification questions can be read aloud.

Generating the draft costs 2 credits each time. The interview itself does not
call a paid model. The new `clerking` Edge Function checks the user's session,
charges through existing credit controls, reserves the global provider budget,
limits output to 3,000 tokens and refunds reported generation failures. There is
no additional migration: it uses the existing usage-control RPCs. Existing
DeepSeek credentials are required. `supabase functions deploy clerking` deploys
it; the repository workflow also deploys all function directories when the
Supabase access-token secret is configured.

The frontend probes the authenticated endpoint with GET, which is refused with
405 before billing when the function exists. A 404 disables draft generation;
patients can still complete the local interview. A GET health check never
charges credits. Configure the repository's `SUPABASE_ACCESS_TOKEN` Actions
secret to enable its existing function deployment job, or deploy `clerking`
through an authenticated Supabase CLI. Never paste access tokens into chat.

The draft prompt prohibits invented findings, implied negative histories and
silent resolution of contradictions. Every substantive section must include
exact supporting quotations from the interview; server and client validate
those quotes. Quote validation cannot prove that the model's interpretation is
clinically correct. Clinician review remains required, and original patient
words are available beside every section. Uncertainty should be retained and
returned as follow-up questions. Clinician examination findings are copied
verbatim from separate clinician input and are never generated by the model.

The note can be edited, copied, downloaded as text or printed/saved as PDF.
Print starts the continuation on a second page and clarification questions on
an additional page. Long narratives may use further pages. Exports are labelled
as drafts until clinician review is confirmed. Changing the original interview
blocks export of a stale draft until it is regenerated. Editing the note clears
its review confirmation. Cancelling a request may still consume credits if the
server completed it; the UI reconciles with the server's budget.

Patient input and drafts stay in React memory, not local storage, conversations
or account tables. Reloading or navigating away discards the history. The page
uses PostHog's no-capture/mask classes; session replay is already disabled.
Speech may be processed by the browser's speech service and submitted written
history is sent to the configured AI provider. No patient content or raw model
output is logged by the new function. These choices are not a claim of HIPAA
compliance or a replacement for a clinical record system.

Validation:

```sh
node --test supabase/functions/clerking/contract.test.mjs
node scripts/test-clerking-edge.cjs
node scripts/test-ai-usage-limits.cjs
npx tsc --noEmit
npm run build:static
```

Mocked browser checks exercised spoken prompts, microphone transcripts, draft
generation, source visibility, missing sections, editing/review state, stale
export blocking, provider failure retention, mobile overflow and PDF pagination.
No real patient history, paid provider request or database write was used.
Browser fixture networking blocks analytics scripts, which causes the same
unhandled `Event` observed on the unchanged Library page; no additional page
error occurred in the clerking flow. Live speech accuracy and live AI output
quality need supervised evaluation before clinical use.
